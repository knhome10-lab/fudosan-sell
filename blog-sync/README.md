# 戸建てリノベINFO 新着コラム自動化ワークフロー

参照元ブログ「戸建てリノベINFO」(https://smile.re-agent.info/blog/) に新しい記事が掲載されたら、KNホームの売却依頼LPの「お役立ちコラム」として書き換え・公開するためのワークフローです。

**実行方法**: 手動トリガーのみ。ユーザーが「ブログの新着チェックして」のように依頼した時に、Claudeが以下の手順を実行します（スケジュール実行はしません）。

## ファイル構成

- `log.json` — これまでに確認・処理した参照元記事の一覧（post_id, 日付, タイトル, 処理状況, 対応するKNホームコラムのファイル名）
- `check_new_articles.py` — 取得したアーカイブページのテキストから、log.jsonに無い新着post_idを抽出するスクリプト
- `README.md` — 本ファイル

## 実行手順（Claude向け）

### 1. 新着検知
1. 今日の年月（例: 2026年9月なら `202609`）で `https://smile.re-agent.info/blog/?m=YYYYMM` を取得する
2. 月初（1日〜3日目安）の場合は前月分 `?m=YYYYMM`（前月）も追加で取得する
3. 取得したテキストをそれぞれ `archive_YYYYMM.txt` として保存する
4. `python3 check_new_articles.py --log log.json archive_*.txt` を実行し、新着記事（post_id・日付・URL）を古い順に取得する
5. 新着が0件なら「新着記事はありませんでした」とユーザーに報告して終了する

### 2. 記事ごとの処理（新着を古い順に1件ずつ）
1. 記事の全文を `https://smile.re-agent.info/blog/?p=<post_id>` から取得する
2. 内容を確認し、KNホーム（埼玉・春日部の空き家・相続不動産売却専門）の読者に向けた「売却」目線の切り口を考える
   - 売却との関連が強い記事（法改正・金利・税制・修繕・リフォーム判断など）→ しっかりした構成＋FAQ 2〜3問
   - 関連が弱い記事（新技術紹介、購入者向けライフスタイル記事など）→ 軽めの情報提供トーン、FAQなしでも可
   - どうしても売却に紐付けられない場合はスキップし、理由をlog.jsonに記録して次のステップへ
3. 数値・法改正・税制など事実性の高い主張は、参照元記事をそのまま信用せず、WebSearchで一次情報（国税庁・国土交通省・法務省・住宅金融支援機構・モゲチェック等）に当たって裏取りする。誤差があれば修正し、出典を記事末尾に明記する
4. 既存コラム（`column/*.html`）と同じHTMLテンプレートでコラムを作成する
   - CSS変数・nav/breadcrumb/cta-box/info-box/warn-box/compare-table/faq-item のクラス構成は既存ファイルをコピーして流用する
   - JSON-LD: Article（+ FAQPageがあれば）+ BreadcrumbList
   - CTAは電話番号 0800-919-5566、`gtag('event','column_cta_click', ...)` と `phone_click` イベントを踏襲する
   - 著作権配慮のため、参照元の文章をそのまま使わず、構成・切り口を変えて書き直す
   - 法律・税務・投資に関わる内容には「本記事は情報提供を目的としており...助言ではありません」の免責文を入れる
   - 公開日は「記事の実際の掲載日」（今日の日付、または新着記事の実際の検知日）を使う。過去分散配置は第3弾までの旧記事分のみの対応であり、新着記事には適用しない
5. 関連コラム1〜2本と相互リンクを追加する（新規記事側にリンクを貼り、既存記事側にも該当箇所があれば追記する）
6. `column/<slug>.html` として保存する
7. `column/index.html` の記事一覧に日付降順を維持する形でカードを追加する（新しい記事なので基本的に先頭付近に入る）
8. `sitemap.xml` に `<url>` エントリを追加する（lastmodは公開日と同じ）
9. JSON-LDのパース検証を行う（`python3 -c "import re,json; ..."` で全ファイルを確認しゼロエラーを確認）

### 3. 公開
1. `git add -A && git commit -m "..." && git push origin main` を実行する
2. `git fetch origin main && git log --oneline -1 origin/main` でpush成功を確認する

### 4. 記録
1. `LP管理表.xlsx`「改善タスク」シートに1行追加する（参照元記事名・書き換えの切り口・裏取りした場合はその出典を記載）
   - openpyxlで新しいファイル名に保存 → `recalc.py` で再計算 → 元のLP管理表.xlsxに上書きコピー、という手順を踏む
2. `log.json` に処理した記事を追記する（status: "published" または "skipped"、kn_home_file）

### 5. 報告
- 処理した記事のタイトルと公開URL（コラムファイル名）を一覧でユーザーに報告する
- スキップした記事があれば理由とともに報告する
